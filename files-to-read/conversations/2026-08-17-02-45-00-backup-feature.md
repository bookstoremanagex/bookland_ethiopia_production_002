## Summary
Built the admin **Backup** feature (menu on/off system from prior sessions is complete). The feature is a new admin page listing local backup records with a "New Backup" button that generates a full MySQL SQL dump, downloads it to the user's machine, and records success/failure in `local_backup_records`.

## Key decisions
- **No mysqldump**: the `mysql`/`mysqldump` CLI is not installed on this machine, so the dump is generated programmatically via Prisma raw queries (`information_schema.tables`, `SHOW CREATE TABLE`, `SELECT *` with a custom SQL value escaper for strings/dates/buffers/bigints).
- **Filename format**: `backup_[ethiopian YYYY-MM-DD]_[time]_[gregorian YYYY-MM-DD]_[time].sql` (e.g. `backup_2018-12-11_02-16-56_2026-08-17_02-16-56.sql`). Ethiopian date via `convertToEthiopian`.
- **`local_backup_records` table did NOT exist** in the connected DB (`temporary_db`) → `P2021`. Per user approval, created the table via raw SQL (no prisma CLI, no schema.prisma change): columns `id` (AI PK), `databaseName`, `fileSizeBytes`, `status` (default `'success'`), `createdAt` (DATETIME(3) default now), plus index `local_backup_records_createdAt_idx`.
- Dump files are also written to `local_backups/` on the server so records can be re-downloaded via a route handler; deleting a record also deletes its file.
- `.env` DATABASE_URL is currently `temporary_db` (bookland_main_db line is commented out). Dump uses `DATABASE()` so it targets whichever DB is connected.
